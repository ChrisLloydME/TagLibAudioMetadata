# Field-level write validation

Audited revision: commit `ebd21c7b1aa9be607133fc4a9de02d2c7890f42f` (`docs: prepare 0.8.3 release`, 2026-11-25), package version `0.8.3`. The pinned native dependency is TagLib `2.3.1` (tag `v2.3.1`, source commit `54ae7d8ac45755e286a5c574280f48d5bef93aef`), binary revision `2` from release tag `taglib-binary-2.3.1-r2`, asset `TagLibAudioMetadataTagLib-2.3.1-apple-dynamic.xcframework.zip` with the manifest checksum. The audit ran on Swift `6.4.2` / Xcode `27.2` on macOS arm64. Production write behavior was not changed for this audit.

This page is the field-by-field write contract for the current implementation. It is a single matrix split into category tables so that a missing combination remains visible rather than hidden in prose: **100 semantic keys**, grouped by category and repeated on every row, across every recognized format family and both ID3v2 tag versions. Each category has its own table; rows name every unsupported family explicitly. The Swift registry and mapping catalog remain authoritative; this page is a reviewed view of what the executable paths actually accept and reject.

## How this audit was built

- Every semantic key, category, value shape, PropertyMap alias, native target, preferred-write flag, capability state, and format descriptor was read from `MetadataFieldSchema.swift`, `MetadataMappingCatalog.swift`, `FormatCapability.swift`, `TLFormatRegistry.mm`, and the generated reference pages. The registry contains 100 canonical keys in 14 categories; the bridge recognizes 22 format families covering 37 extensions.
- The write paths were traced through `MetadataPatch` validation, `MetadataNativePlanning`, `replaceBasicMetadata`/`updateBasicMetadata`, raw merge/replace, structured payload validation, the Objective-C++ bridge, the pinned TagLib 2.3.1 codecs, the staging/verification transaction, and the low-level public bridge.
- Committed fixture tests were run for the relevant families. A temporary audit probe (not committed) exercised boundaries, format exceptions, explicit removal, custom keys, ID3v2.3 layouts, WAV INFO fallback, ASF text arrays, and the MP4 `rate` atom. Its scenario names and observations are recorded in [Findings and minimal reproductions](#findings-and-minimal-reproductions).
- Native inspection used independent test readers for MP4 atoms, ID3v2 frames, ASF attributes, RIFF chunks, FLAC/Vorbis comments, APEv2 items, and Ogg comments, not the semantic reader whose result was being checked.
- The matrix labels evidence as runtime-verified, source-supported, or unverified. A passing fixture test is evidence for the tested layout, not a universal format claim.

## Terms used in the matrix

**Unsupported** means `FormatCapability.writeSupport(for:)` returns `.unsupported` for that field and family: there is no writable mapping, or the mapping is explicitly gated. Typed and Basic writes reject before staging.

**Read-only** means a native location exists and is readable or preservable, but the typed writer does not advertise or implement a write for it. Examples are the ID3v2.3 independent-date frames, `.rate`, the RIFF INFO registrations, and `trackerName` on S3M/IT.

**Unverified** means a code path or mapping exists but this repository has no runtime fixture or independent observation for that exact combination. The row says `U` rather than implying that a configured label is proof.

**Conditional** means validation accepts an input that the writer cannot represent or verify. The matrix states the later rejection and the unchanged-file outcome. The ASF text-array rows are the current example.

**Basis codes** identify why a restriction exists:

- `B1` — documented native encoding constraint (frame/atom/attribute type, width, separator, or size).
- `B2` — limitation or behavior of the pinned TagLib 2.3.1 codec (including post-write verification).
- `B3` — public Swift API type or schema range (for example `Int`, non-empty `String`, four-state enum).
- `B4` — field semantics (single versus multi-value, independent dates, role qualification, dedicated artwork/advisory).
- `B5` — data-integrity or preservation safeguard (alias retirement, exact untouched-owner checks, atomic rollback).
- `B6` — package mapping policy or scope (a family is intentionally not mapped, a tracker allowlist, MP4-exclusive registration, typed `.rate` withheld).
- `B7` — no established justification, or a documented mismatch between validation and native encoding. These are current findings, not endorsements.

**Evidence tags** name the basis for a row: `R` is a committed runtime test; `R*` is the temporary audit probe described in the findings; `S` is source inspection; `U` is unverified. `E-MP4`, `E-ID3`, `E-XIPH`, `E-APE`, `E-ASF`, `E-WAV`, `E-TRACKER`, and `E-API` are the committed suites and capability checks listed under [Validation performed](#validation-performed).

## API surfaces

The **API behavior** column states where the five write styles differ for that field.

- **P — `MetadataPatch`** is the typed semantic path. It validates value kind, schema range, role/artwork/custom routing, format `writeSupport`, ID3v2.3 date policy, and number-text conflicts before staging, then plans the exact native target. `MetadataPatch` also exposes `customFields`, `explicitAdvisory`, `artwork`, and `numberText`.
- **B — Basic** is `replaceBasicMetadata` / `updateBasicMetadata`. It projects `BasicMetadata` through the same typed planner. Empty Basic strings remove fields; a Basic `"0"` removes scalar track/disc/movement/BPM/TV numbers but is a present value for Store IDs and media kind; YEAR text is checked by the frozen prefix validator; `trackNumberText`/`discNumberText` must agree with the numeric pair; role, tracker, and custom fields are not represented. The older low-level `writeTagMetadata(_:to:verification:expectedVersion:)` takes the Objective-C `TagLibAudioMetadata` model and is a separate surface: it lacks the MP4-exclusive fields, validates numbers at the bridge, and rejects any ID3v2.3 destination.
- **S — Structured** is `writeStructuredMetadataWithVerification`. It writes exact ID3 frames, MP4 atoms, ASF attributes, PropertyMap properties, or artwork collections. It does not apply schema value kinds, so the caller is responsible for the native type. `properties` requires `includeProperties: true`; ID3 `APIC`/`COMM`/`USLT` must use the dedicated collections; MP4 comments/lyrics collections are rejected; MP4 atom types outside the supported list are rejected; ASF GUID attributes are inspection-only; ID3v2.3 date frames are rejected while non-date frame upserts are allowed.
- **R — Raw** is `applyRawMetadataPatch` (merge) and `writeRawMetadataPropertyMap(Values)WithVerification` (replace). Keys are prefixless TagLib PropertyMap keys; native `----:` keys are rejected. Merge preserves array boundaries, duplicate values, whitespace, and empty strings; an empty value array is rejected (`use removingKeys`), while an empty scalar value removes that key. The whole-map merge variant treats an all-empty array as removal. Replace trims/drops empty values and replaces the complete visible map. Neither surface applies semantic kind/range checks except the MP4 numeric validator; both verify the complete visible PropertyMap unless verification is explicitly disabled.
- **L — Low-level public bridge** (`TagLibMetadataExtractor.writeMetadata`, `writeRawPropertyMap`, `writeRawPropertyMapValues`, `writeStructuredMetadata`, `writeTrackNumber`, `writeTrackNumberText`) performs its own validation and its own atomic mutation. Except for the in-place package-internal entry points used by the facade, direct raw/structured/track-number L writes to an existing ID3v2.3 file are rejected with domain `TagLibMetadataExtractor`, code `9290`; `writeMetadata` (the Basic replacement bridge) rejects v2.3 with code `9261`.

The complete transaction, durability, and preservation behavior is owned by [Transactions](../explanation/TRANSACTIONS.md) and [Preservation](../explanation/PRESERVATION.md); rows here link to the field-level consequence rather than duplicating those contracts.

## Raw keys without a semantic mapping

Raw merge/replace and structured `properties` accept keys that do not resolve to one of the 100 semantic schemas. Those keys are outside this matrix. They share the raw rules above: prefixless PropertyMap keys, `----:` rejection, hidden-internal-key rejection in the merge path, NUL rejection, non-empty array rules, and complete visible-map verification. A raw key is not an alias and does not acquire a semantic reader, range check, alias-retirement rule, or native-ownership promise. A key that resolves through `MetadataFieldRegistry.schema(forPropertyMapKey:)`, including the qualified `PERFORMER:`, `INVOLVEDPEOPLE:`, `MUSICIANCREDITS:`, `COMMENT:`, and `LYRICS:` prefixes, belongs to that schema's rows. Use the field reference's [lookup rules](FIELDS.md#lookup-and-ownership-rules) and [Preservation](../explanation/PRESERVATION.md) for the raw contract. Custom keys supplied through `MetadataPatch.customFields` are schema-known-key checked and normalized; arbitrary raw keys are not.

## Shared rules that apply to every row

- **Atomic outcome.** Every facade write is staged on a sibling copy and committed only after validation, native write, re-read verification, and a version check. A rejection, verification failure, or stale version leaves the destination byte-for-byte unchanged. Symlinks, hard links, non-regular files, and setuid/setgid files are rejected. See [Transactions](../explanation/TRANSACTIONS.md).
- **ID3v2.3 dates.** The transaction captures the date-frame signature of an existing ID3v2.3 tag before the operation and rejects any change at commit. Typed and structured date edits reject before staging; Basic rejects when a date value changes; raw facade edits that would change a date frame fail verification. Direct low-level bridge writes reject v2.3 entirely. This protects `TYER`, `TDAT`, `TORY`, `TDRL`, `TDOR`, `TDRC`, and their TXXX descriptions.
- **Empty, zero, and removal.** `.text("")` and `.values([])` are validation errors, not deletion aliases; each `.values` element must be non-empty after trimming. NUL is rejected in every text/key/value path. `.remove` is the explicit deletion request. For typed integers, `0` is a present value for movement, BPM, Store IDs, media kind, TV numbers, and `.rate`; it is rejected for track/disc components, where `.remove` is the only way to unset a component. Basic `"0"` is a removal signal only for its scalar-number set. `.boolean(false)` is a present `0`, not absence.
- **No package length or cardinality preflight.** Text length and `.values` cardinality have no package-level maximum; duplicates are retained. Native limits are the ID3v2 frame size (32-bit in v2.3, syncsafe 28-bit in v2.4), MP4 atom/item size (32-bit), Xiph comment length (32-bit little-endian), APE item length (32-bit), ASF descriptor lengths, and tracker fixed-width fields. Artwork is the exception: each image must be non-empty and no larger than `UInt32.max`, and APE accepts at most one front image. Where the pinned codec rejects a value at save/verification time the row marks the limit as unverified.
- **Number pairs and formatted text.** `.track` and `.disc` share their native pair with `.trackTotal` and `.discTotal`. Editing one component preserves the omitted sibling: the planner uses the unique canonical native value, then a single unambiguous legacy candidate; conflicting, malformed, or opaque evidence rejects with `ambiguousNumberRecovery`. Supplying `MetadataPatch.numberText` together with a typed field for the same pair rejects with `conflictingNumberRepresentations`; malformed or out-of-range text rejects with `numberTextMismatch`/`integerOutOfRange`. Presence is intent: `n/0` and a slash followed by an empty total store an explicit zero and do not recover the old total. `.remove` un-sets a component; typed `.integer(0)` is rejected for track/disc and is a present zero for movement. ASF rejects a zero number with a positive total.
- **Alias retirement.** A typed edit removes the field's consumer-facing PropertyMap aliases and its registered native aliases for the selected family before writing the exact target, then verifies that untouched owners did not change. MP4 freeform descriptions are case-insensitive identities; ID3 TXXX descriptions are case-insensitive; ASF common attributes are retired only when the corresponding Tag property changes. Raw/structured writes do not perform the same semantic alias cleanup unless the caller addresses the exact keys.
- **Unsupported versus raw escape.** When a family is unsupported, typed and Basic writes reject. Raw or structured calls can still attempt a prefixless PropertyMap key or a native frame that TagLib exposes, but that is outside the semantic mapping, is not range-checked by the schema, and is not covered by this matrix's write promise.

## Alias and fallback destinations affected by a write

The native target in the matrix is the write destination. These read-compatible aliases are retired or preserved according to the edited field, so a read that used a fallback cannot resurrect an old value after an explicit write:

- **MP4 freeform read aliases** retired for the edited field: `publisher` (`LABEL`, `PUBLISHER`), `conductor` (`CONDUCTOR`), `work` (`WORK`), `mediaType` (`MEDIATYPE`, `MEDIA`, `MEDIA TYPE`), `encodedBy` (`ENCODEDBY`; `ENCODING` is deliberately not retired), `encoderSettings` (`ENCODERSETTINGS`, `ENCODING`), `movementNumber` (`MOVEMENTNUMBER`), `movementCount` (`MOVEMENTCOUNT`), `releaseDate` (`RELEASEDATE`), `originalReleaseDate` (`ORIGINALDATE`, `ORIGINAL YEAR`), `standaloneDate` (`DATE`), the iTunes Store-ID and media-kind fields, `artistType`, `releaseType`, `releaseStatus`, `releaseCountry`, `contentGroup` (`CONTENTGROUP`), and `grouping` (`GROUPING`). The engine PropertyMap spellings of the same schema are also retired, except for `YEAR`, so a `year` edit does not consume the independent `DATE` alias.
- **MP4 fallback source.** A field without its native atom may be read from one of those freeform aliases. An unrelated save preserves the fallback; editing the field deletes the alias and writes the catalog target. The `©day`/`DATE`/`RELEASEDATE`/`ORIGINALDATE` owners are independent; an engine `DATE` projection does not authorize changing an unedited date owner.
- **ID3 TXXX aliases.** Editing a non-date field removes every TXXX frame whose description resolves to the same schema, then writes the exact frame or description. `barcode` retires `BARCODE`/`UPC`/`EAN` descriptions; `catalogNumber` retires its catalog variants; the MusicBrainz and AcoustID fields retire their space/underscore variants. `comment` and `lyrics` are special: a typed scalar removes every qualified `COMM`/`USLT` entry, not just one description.
- **Xiph and APE aliases.** Editing a field removes its schema PropertyMap spellings and every registered native target for the same family before writing the exact target. `YEAR` and independent `DATE` are never retired by editing the other; the APE spellings `ALBUM ARTIST`, `MIXARTIST`, `MUSICBRAINZ_ALBUMTYPE`, and `MUSICBRAINZ_ALBUMSTATUS` are the canonical APE targets, not fallbacks.
- **ASF common aliases.** `Title`, `Author`, `Album`, `Description`, and `WM/Genre` attributes that duplicate the common Tag projection are removed only when the corresponding common field changes. Other ASF attributes, including case aliases of an edited custom key, are preserved unless that exact custom field is edited.
- **WAV/RIFF fallback.** A field may be read from RIFF INFO when ID3 does not own it. A typed/Basic edit writes ID3v2 and leaves INFO intact; deleting the ID3 owner then exposes the retained INFO value, and post-write verification rejects that outcome rather than reporting success. A raw merge can update the existing INFO PropertyMap key; a raw RIFF ID is not that key.
- **Catalog read-only aliases.** Non-preferred native targets marked `(read)` in the field registry (for example the ID3v2.3 date frames) are readable/preserved but never typed write destinations. `MetadataMappingCatalog` remains the exact list.

## Field interactions that change a write

- **Dates.** `year`, `standaloneDate`, `releaseDate`, and `originalReleaseDate` are independent owners. Editing one writes its exact target and does not synthesize, truncate, or clear another. The one exception is policy, not projection: an existing ID3v2.3 tag makes all four typed date edits read-only.
- **Encoded By and Encoder Settings.** `encodedBy` writes `©enc`/`TENC`/`ENCODEDBY`/`WM/EncodedBy`; `encoderSettings` writes `©too`/`TSSE`/`ENCODING`/`WM/EncodingSettings`. On MP4, editing one retires its own freeform alias set and not the other's. The `ENCODING` engine projection is allowed for `encoderSettings` edits and is not a destination for `encodedBy`.
- **Content Group, Grouping, and Work.** These are independent owners: `©grp`/`TIT1`/`CONTENTGROUP`/`WM/ContentGroupDescription`, `GROUPING`/`GRP1`, and `©wrk`/`TXXX:WORK`/`WORK`. A missing Content Group does not fall back to Grouping or Work. MP4 verification permits the engine's `GROUPING` projection only for an explicit Content Group edit.
- **Artist and Artists.** `artist` uses the native performer/artist owner (`TPE1`, `©ART`, `ARTIST`, `Author`, `IART`); `artists` is a separate multi-value field (`TXXX:ARTISTS`, `----:com.apple.iTunes:ARTISTS`, `ARTISTS`, `WM/ARTISTS`). Editing one does not write the other.
- **Comments and lyrics.** Typed `.comment`/`.lyrics` are scalar owners of the complete qualified ID3 collection, or `©cmt`/`©lyr`/`Description`/`WM/Lyrics` on the other surfaces. Structured `comments`/`lyrics` collections are a separate surface, supported only where the format dispatch allows them.
- **Number pairs.** `track`/`trackTotal` and `disc`/`discTotal` share one native pair; editing one component resolves and preserves the sibling. `numberText` is an alternative representation for the same pair and cannot be combined with typed components for that pair. Movement number/count are independent MP4 atoms and shared `MVIN` text on ID3.
- **ASF text arrays.** `.values` is accepted by the schema for the multi-value ASF fields but fails post-write verification; use `.text` or native structured attributes. This is a writer limitation, not a schema rule.
- **Custom fields.** A custom key that resolves to a schema-known name is rejected. MP4 preserves an unchanged native freeform spelling and collapses case aliases only when the edited key changes; ASF writes the normalized key as a native Unicode attribute.

## Format coverage ledger

The 22 families and 37 extensions map to the matrix surfaces as follows. Every key has at least one row; every family omitted from a key's supported rows is named in that key's **Unsupported** row.

- **ID3v2.3** — `mpeg-id3` (`mp3`, `mp2`), `mpeg-aac` (`aac`), `wav`, `aiff` (`aiff`, `aif`, `aifc`, `afc`), `trueaudio` (`tta`), `dsf`, `dsdiff` (`dff`, `dsdiff`). Used only when the existing ID3v2 tag is v2.3. 83 surface rows, including four read-only date rows; the 17 MP4-exclusive keys name ID3v2.3 as unsupported.
- **ID3v2.4** — the same containers, used when the existing tag is v2.4 or a new ID3v2 tag is created (new tags default to v2.4). 83 rows.
- **MP4** — `m4a`, `m4r`, `m4b`, `m4p`, `mp4`, `m4v`, `3g2`. 99 rows, including the read-only `.rate` row; `trackerName` is the only key without an MP4 target.
- **Vorbis comment** — `flac`, `ogg-vorbis` (`ogg`), `ogg-opus` (`opus`), `ogg-flac` (`oga`), `ogg-speex` (`spx`). FLAC uses a Vorbis comment block; the Ogg family uses Xiph comments. 83 rows.
- **APE item** — `ape`, `wavpack` (`wv`), `musepack` (`mpc`). 83 rows.
- **ASF attribute** — `wma`, `asf`. 57 rows; the remaining 43 keys name ASF as unsupported.
- **RIFF INFO** — `wav` only, and only as a read/preserve registration; AIFF/AIFF-C have ID3v2 but no INFO surface. 10 read-only rows; every other key names RIFF INFO as unsupported.
- **Tracker PropertyMap** — `s3m`, `it`, `xm` for title and comment; `xm` for `trackerName`; `mod`, `module`, `nst`, `wow` are read-only; `shn` is read-only. The custom-field row is conditional: XM accepted the API call but failed verification.
- **Matroska** — no registered extension. Only `tvEpisode` and `tvSeason` have target-only registrations; both are `.unsupported` and have no native codec.

Read-only surfaces that nevertheless have native registrations are called out in their rows: ID3v2.3 date frames, `.rate` on MP4, the RIFF INFO column, and `trackerName` on S3M/IT. `MOD`, `Shorten`, and the other read-only families never reach a typed write because `isWritableFormat` is false.

## Format-specific exceptions not repeated in every row

- **TrueAudio.** A mixed APEv2 surface with any item other than the encoder provenance marker rejects before commit because the pinned handler cannot reconcile APEv2 and ID3. Removing the secondary tag is outside this package's write API. See [Formats](FORMATS.md#id3v2-and-mixed-tag-surfaces).
- **DSF/DSDIFF.** Native ID3 frame upserts, PropertyMap deltas, and artwork are supported; structured comments/lyrics collection replacement is rejected. Typed `.comment`/`.lyrics` remain supported through their scalar owners.
- **MPEG/ID3 and raw AAC.** Creating the first ID3v2 tag promotes visible legacy fields before saving; ID3v1 and secondary APE bytes are preserved. Direct low-level v2.3 writes are rejected.
- **FLAC.** Semantic writes use the Vorbis comment; a secondary ID3 tag is readable/preserved but is not a semantic write destination.
- **MP3/MP2.** Semantic writes use ID3v2; a secondary APE or ID3v1 tag is readable/preserved but is not a semantic write destination.
- **WAV/AIFF.** Typed and Basic writes use ID3v2. RIFF INFO is preserved; a typed deletion that exposes a retained INFO value fails verification rather than reporting a false success. Structured `id3v2Only` strips INFO after writing ID3.
- **MP4.** Structured `comments`/`lyrics` collections are rejected before staging; typed `.comment`/`.lyrics` use `©cmt`/`©lyr`. Unsupported atom types are rejected, not silently ignored. `covr` is edited through artwork, not as a scalar atom.
- **ASF.** Common fields duplicated as custom attributes are cleared only when the common field changes. Structured `int` updates retain an unambiguous WORD/DWORD width, and ambiguous or overflowing updates reject. GUID attributes are inspection-only. Text arrays accepted by the schema fail post-write verification. Custom fields are API-owned: they are written as native Unicode attributes even though the `<explicit key>` profile has no ASF catalog target.
- **APE family.** One front image is writable; a multi-image replace is rejected by the bridge. APE text arrays are stored NUL-separated within one item.
- **Trackers.** The allowlist is title and comment for S3M/IT, plus `trackerName` for XM; MOD and Shorten are read-only. No artwork path exists. Fixed-width fields can normalize, pad, or truncate text.
- **Matroska.** No extension is registered and no codec is implemented. The two target registrations are documentation of a gated future mapping, not support.

## The matrix

The matrix is split into one table per registry category so that each table remains scannable. Every table uses the same ten columns, and the semantic key is repeated on every row. The column split separates the dimensions that the earlier prose cells compressed together: accepted kinds, limits, normalization, removal, rejection layer/timing, API behavior, and the rationale/evidence behind each row. Rows are grouped by key; within a key, the surfaces run in this order: ID3v2.3, ID3v2.4, MP4, Vorbis, APE, ASF, RIFF INFO, tracker, Matroska, then the explicit unsupported row.

### How to read the columns

- **Semantic key** — the stable `MetadataFieldKey` name; repeated for every surface of that field.
- **Surface and formats** — the native tag surface and the recognized extensions it applies to. “ID3 containers” means `mpeg-id3` (`mp3`, `mp2`), `mpeg-aac` (`aac`), `wav`, `aiff` (`aiff`, `aif`, `aifc`, `afc`), `trueaudio` (`tta`), `dsf`, and `dsdiff` (`dff`, `dsdiff`). `ID3v2.3` and `ID3v2.4` are separate rows because their frames and date rules differ.
- **Native destination** — the exact frame, atom, freeform key, attribute, or PropertyMap key. `(read-only)` marks a native slot that is preserved but is not a typed write destination. `(number component)` and `(total component)` are the two halves of one native pair.
- **Accepted input** — the typed-patch kinds accepted by `MetadataPatch`; Basic, structured, and raw differences are in **API behavior**. `.text`, `.values`, `.integer`, `.boolean`, and the dedicated artwork/advisory/custom routes are named explicitly. `none` means no typed value is accepted.
- **Constraints** — schema ranges, native widths, cardinality, key grammar, artwork size, and fixed-width limits. A native width here is enforced at the layer named in **Rejection**, which may be later than Swift validation.
- **Encoding and normalization** — the native encoding, separator behavior, case rules, and literal/alias normalization. Alias retirement is stated where a typed edit removes a read-compatible spelling.
- **Removal and zero** — what `.remove` does, whether empty text/arrays are accepted, and whether `0` or `false` is a present value or an absence sentinel. Sibling-preservation rules for number pairs are stated here.
- **Rejection: layer → outcome** — the error, the layer that raises it (Swift validation, transaction baseline, bridge/codec, or post-write verification), the timing relative to staging, and whether the destination remains unchanged.
- **API behavior** — compact differences across the five write surfaces. `P` = `MetadataPatch`; `B` = `replaceBasicMetadata`/`updateBasicMetadata`; `S` = `writeStructuredMetadataWithVerification`; `R` = raw merge/replace; `L` = the low-level public bridge. `planner` means the same typed planner; `exact target` means the exact native target without schema-kind validation; `prefixless key` means a raw PropertyMap key.
- **Basis and evidence** — `B1`–`B7` are the basis codes defined above; `R` is a committed runtime test, `R*` the temporary audit probe, `S` source inspection, and `U` unverified. `E-MP4`, `E-ID3`, `E-XIPH`, `E-APE`, `E-ASF`, `E-WAV`, `E-TRACKER`, and `E-API` identify the committed evidence bundles listed under [Validation performed](#validation-performed). `U` marks combinations with no fixture or runtime observation; its absence means at least bundle/source evidence for the surface, not universal conformance.

## Findings and minimal reproductions

These are current-behavior observations. None of them changed production code in this audit.

### F1. ASF text arrays pass validation but fail post-write verification

Fields: `artist`, `albumArtist`, `genre`, `composer`, `conductor`, `remixer`, `producer`, `lyricist`, `artists`, `originalArtist`, `mood`, `language`. Format: ASF/WMA. Path: `MetadataPatch` accepts `.values` for these multi-value schemas (`Sources/TagLibAudioMetadata/MetadataSnapshotPatch.swift:220`), the ASF planner selects the PropertyMap mechanism (`Sources/TagLibAudioMetadata/MetadataNativePlanning.swift:160`), the bridge applies it through TagLib's ASF `setProperties` (`Sources/CTagLibBridge/Internal/TLPropertyMapDelta.inc:193`), and the post-write comparison rejects the result (`Sources/TagLibAudioMetadata/MetadataSnapshotPatch.swift:931`).

```swift
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(fields: [.artist: .values(["A", "B"])]),
    to: wmaURL
)
```

Observed: `TagLibManagerError.verificationFailed` ("Patched field artist differs after save"); destination unchanged. The same result was reproduced for all twelve fields. `.text("A; B")` succeeds and round-trips. Basis `B2`/`B7`; use `.text` or native structured ASF attributes until the verifier can represent the array.

### F2. `releaseType` rejects `.values` although the catalog shape is `textArray`

Field: `.releaseType`; all formats. The schema is not multi-value (`Sources/TagLibAudioMetadata/MetadataFieldSchema.swift:449`) while the catalog declares `shape: .textArray` (`Sources/TagLibAudioMetadata/MetadataMappingCatalog.swift:421`). `acceptedPatchValueKinds` therefore returns only `.text` (`Sources/TagLibAudioMetadata/MetadataFieldSchema.swift:228`).

```swift
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(fields: [.releaseType: .values(["Album", "Live"])]),
    to: m4aURL
)
```

Observed: `MetadataPatchValidationError.incompatibleValue` before staging; destination unchanged. Basis `B7`: no justification for the single-valued restriction is recorded; either the schema or the catalog should be corrected, but changing either changes the public contract.

### F3. `.rate` is typed-read-only but the MP4 `rate` atom is writable through StructuredMetadata

Field: `.rate`; MP4. The catalog withholds typed writes (`Sources/TagLibAudioMetadata/MetadataMappingCatalog.swift:1056`) and `writeSupport` rejects the format (`Sources/TagLibAudioMetadata/FormatCapability.swift:83`), but structured atom validation accepts `rate` as `uint` or `int` and the item factory resolves a 16-bit integer.

```swift
try TagLibMetadataManager.writeStructuredMetadataWithVerification(
    .init(mp4Atoms: [.init(key: "rate", type: "uint", value: "80")]),
    to: m4aURL
)
```

Observed: accepted; `BasicMetadata.rate == 80`. Basis `B6`/`B7`: "read-only" describes the typed policy, not a native impossibility. The scale and interoperability of the value remain unverified.

### F4. ASF BPM is written as a Unicode string with no numeric-width check

Field: `.bpm`; ASF/WMA. The typed schema allows `0...Int32.max` (`Sources/TagLibAudioMetadata/MetadataFieldSchema.swift:263`), the ASF planner uses the PropertyMap path, and `SetPropertyMapString` emits the decimal text (`Sources/CTagLibBridge/Internal/TLPropertyMapCodec.inc:173`).

```swift
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(fields: [.bpm: .integer(70000)]),
    to: wmaURL
)
```

Observed: accepted; native `WM/BeatsPerMinute` is a Unicode attribute (ASF type 0) with text `"70000"`, and the semantic readback is `70000`. The native ASF attribute is typed numeric; the writer does not enforce its width. Compare MP4, where `.bpm: .integer(32768)` is rejected by the bridge. Basis `B7`.

### F5. ASF `originalReleaseDate` accepts full date text in a year-named attribute

Field: `.originalReleaseDate`; ASF/WMA. The catalog destination is `WM/OriginalReleaseYear` (`Sources/TagLibAudioMetadata/MetadataMappingCatalog.swift:118`), but the typed planner and bridge apply arbitrary text.

```swift
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(fields: [.originalReleaseDate: .text("2020-05-01")]),
    to: wmaURL
)
```

Observed: accepted; the native attribute contains `2020-05-01`, and the semantic readback is the full date. No year-only validation or truncation exists. Basis `B7`.

### F6. ID3v2.3 multi-value text is NUL-separated by the pinned codec

Fields: multi-value ID3v2 fields (for example `.artist`). Format: ID3v2.3. The typed planner writes a `StringList` through `TagLib::ID3v2::TextIdentificationFrame::setText` (`Sources/CTagLibBridge/Internal/TLStructuredMutation.inc:599`).

```swift
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(fields: [.artist: .values(["A", "B"])]),
    to: id3v23URL
)
```

Observed: `TPE1` contains `A` NUL `B`; the package reads and verifies two values. ID3v2.3 conventionally separates multiple values with `/`, so third-party interoperability is unverified. Basis `B2`/`B1`; this is codec behavior, not a package rejection.

### F7. RIFF INFO targets are advertised as preferred writes but are unreachable from typed writes

Fields: the ten RIFF mappings (`title` INAM, `artist` IART, `album` IPRD, `year` ICRD, `track` ITRK, `comment` ICMT, `genre` IGNR, `composer` IMUS, `copyright` ICOP, `language` ILNG). Format: WAV. The catalog marks each target `preferredWrite: true`, so `schema.capability(for: .riffInfo)` reports `.native`, but `FormatCapability.metadataFieldFormats` never adds `.riffInfo` (`Sources/TagLibAudioMetadata/FormatCapability.swift:55`), and the WAV planner selects the ID3v2 frame branch (`Sources/TagLibAudioMetadata/MetadataNativePlanning.swift:219`).

```swift
// WAV has INFO INAM = "Info Title"
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(fields: [.title: .text("Typed Title")]),
    to: wavURL
)
```

Observed: ID3v2 `TIT2` becomes `Typed Title`; RIFF `INAM` remains `Info Title`. A raw merge of `TITLE` updates an existing INFO key; a raw merge of `INAM` creates an ID3 `TXXX:INAM` instead. Basis `B7`: the preferred-write flag overstates what the typed path does. The documentation now describes RIFF INFO as read/preserve only for semantic writes.

### F8. YEAR validation differs between typed and Basic writes

Field: `.year`. The typed path accepts any non-empty `.text`, including `"not a year"`, on MP4 and ID3v2.4; `replaceBasicMetadata` rejects the same change with `MetadataValidationError.invalidYearText` because it runs the frozen Basic prefix validator (`Sources/TagLibAudioMetadata/TagLibMetadataManager+Write.swift:13` and `:30`).

```swift
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(fields: [.year: .text("not a year")]), to: m4aURL
) // accepted
var basic = try TagLibMetadataManager.readMetadataResult(from: m4aURL)
basic.year = "not a year"
try TagLibMetadataManager.replaceBasicMetadata(basic, to: freshM4AURL) // invalidYearText
```

Basis `B4`/`B6`: the split is documented, but it means the same semantic value is representable through one API and not another.

### F9. MP4 track error messages disagree about the schema minimum

Field: `.track`; MP4. `.integer(0)` is rejected by the schema with `minimum: 1`; `.integer(65536)` is rejected by the native pair validator with `minimum: 0, maximum: 65535` (`Sources/TagLibAudioMetadata/MetadataSnapshotPatch.swift:187` and `:244`).

```swift
// "track must be between 1 and 2147483647; received 0."
// "track must be between 0 and 65535; received 65536."
```

Observed: both reject before mutation; the second diagnostic's minimum is inconsistent with the schema. Basis `B3`/`B7`; this is a diagnostic defect, not a write-behavior defect.

### F10. Tracker custom fields pass validation but fail verification

Field: `.customFields`; XM (`s3m`/`it` have the same shape). The tracker write allowlist is applied to requested semantic fields, not to custom keys (`Sources/TagLibAudioMetadata/MetadataSnapshotPatch.swift:691`), so a custom key reaches the PropertyMap writer.

```swift
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(customFields: ["AUDITTRACKERCUSTOM": .text("X")]),
    to: xmURL
)
```

Observed: `TagLibManagerError.verificationFailed`; destination unchanged. Basis `B2`/`B6`; use a supported semantic field or accept that tracker custom keys are not a writable surface.

### F11. MP4 purchase date has no date validation

Field: `.itunesPurchaseDate`; MP4. The destination is the `purd` text atom, and no date grammar is enforced.

```swift
try TagLibMetadataManager.applyMetadataPatch(
    MetadataPatch(fields: [.itunesPurchaseDate: .text("not-a-date")]),
    to: m4aURL
)
```

Observed: accepted and read back verbatim. Basis `B7`; if a date syntax is intended, it is not implemented.
